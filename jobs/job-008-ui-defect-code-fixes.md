# job-008: 自分のUI総点検指摘のうち「コードで直る分」の一括修正

- status: in-progress(game)
- 難度: 高(GDScript広範囲。ただし1画面ずつ独立)
- 納品方法: A(branch `job/008` → PR)。コードはdiffパッチ+テストで納品(ミラーrepo hp-game-share が参照の正)

## 背景
job-004であなたが挙げた49画面の見た目指摘(47画面に指摘あり、検収済み=抜き取り当たり率100%)のうち、絵の再生成ではなく**コード修正で直る分類**を一括で直してもらう。絵が原因の分(パーツのゴミ・色)は別ライン(パーツ個別生成)が対応するので触らない。

## 対象の仕分け基準
- **やる**: ズレ(整列・中心・マージン不一致)/文言のはみ出し・重なり(位置・サイズ・折り返しの調整)/クリップ漏れ(パーツがフレームからはみ出す)/描画順の異常
- **やらない**: パーツ画像自体のゴミ・白フチ・色ムラ(絵の問題)/デザイン変更(情報の増減・配色変更=オーナー決裁事項)

## 進め方
1. 自分のjob-004指摘一覧(deliverables/job-004/ui_visual_review.md、mergeされてmainにある)を読み直し、上の基準で「コード修正対象」を抽出して冒頭に対象リスト(画面ID×指摘×分類)を出す
2. 深刻度高→中→低の順に修正。1画面ずつ独立したコミットにする(後から画面単位で取捨できる形)
3. 系統的な対策も入れてよい: 数値の直書きが原因の場合、レイアウト定数化・pixel snap・クリップ設定など(ただし見た目の変わる「改善」はしない。指摘の解消だけ)
4. 各修正に対応する検証を付ける: 既存のUIオーバーライド/レイアウト系headlessテストの拡張、または該当画面の座標アサート

## 制約(重要)
- **削除は最小限に**: パッチの削除行が挿入行を大きく超える変更は出さない(出す場合は理由を明記)
- 遷移直後のアサートにはアニメ完了待ちを入れる(job-005の教訓)
- 既存テストの回帰ゼロ。実行ログ同梱

## 完成定義(Yes/No)
- [ ] 冒頭の対象リスト(やる/やらないの仕分け、全指摘をカバー)
- [ ] コード対象の修正パッチ(画面単位)+各画面の検証
- [ ] 回帰テスト全ログ
- [ ] 正直な申告リスト(直せなかった指摘と理由)
