## 20-02-01 目的と決裁済みの骨格

プレイヤーは同行姫の組合せで攻撃の出方を変え、主人公は武器以外の成長要素を担う。参照枠であるBrotatoの武器6枠は「同時に複数の攻撃手段をビルドする」構造の根拠である。本作で確定している枠数は次のとおりで、6枠をそのまま採用しない。

| ID | 決裁済み仕様 | 完成定義 |
|---|---|---|
| W-01 | 姫は武器性能の実体。主人公の武器枠は0、アイテム・防具・ペット等は主人公共通で無制限。 | 主人公の保存/UI/戦闘発生元に武器枠がなく、非武器所持数に上限がない。 |
| W-02 | 姫ごとの武器枠は4。同時同行は最大3人なので最大12武器。 | 固定seed・リリース解像度で12武器が60秒間60fps（16.67ms/frame以下）を維持する。 |
| W-03 | 報酬・店の候補は編成姫の属性に交差する武器のみ。属性効果は一致属性ダメージ増だけで、相性・耐性・状態異常は持たない。 | 非編成属性の候補0件、一致倍率以外の属性演算0件。 |
| W-04 | 獲得した武器は対象姫へ自動装備し、手動配分UIは置かない。 | 全候補に`targetCompanionId`があり、獲得後の所有姫が一意。 |
| W-05 | 同一武器は低Tierから2本ずつ自動合成する。異種・異属性は混ぜない。 | Tier1×4+Tier2×2でTier3×1になる回帰テストが通る。 |
| W-06 | 旧装備セーブは移行しない。 | 旧`subEquipment`・主人公武器を新ランが読まず、新規開始へ誘導する。 |
| W-07 | 武器枠が満杯の姫には、新武器を報酬・店の抽選候補として出さない（ヴァンパイアサバイバー準拠）。 | 各姫の4枠が満杯のとき、新武器が候補へ混入せず、他の有効候補または非武器報酬へ抽選が進む。 |

根拠: ユーザー決裁 2026-07-15、2026-07-22（`decision-log.md`）。

## 20-02-03 データ契約

| フィールド | 固定/変動 | 説明 | 現状 |
|---|---|---|---|
| `weaponDefinitionId` | 固定 | 武器定義ID。現行9IDを移植元にする。 | 実装済み |
| `ownerCompanionId` | ラン内変動 | 所有姫ID。攻撃発生元と表示先を決める。 | 未実装 |
| `targetCompanionId` | 候補ごと変動 | 報酬候補が自動装備する先。 | 未実装 |
| `tier` | ラン内変動 | 同一定義を2本ずつ自動合成する段階。 | 未実装 |
| `attributes` | 定義固定・編成で変動 | 候補フィルタと一致属性ダメージ増だけに使う。 | 未実装 |
| `attackRole` | 定義固定 | 最寄り/ランダム/全周、射程、CD、弾数、貫通等。 | 一部実装済み |
| `damage/cooldown/projectileCount` | 定義固定・強化で変動 | 基礎性能とラン内強化後の値を分離する。 | 旧定義は実装済み |

属性名、姫ごとの対応属性、Tier数上限、重複候補の出現重みは未決である。これらは既決の「属性一致ダメージのみ」を壊さない範囲で、別のデータ仕様にし、ここへ無印で補完してはならない。

## 20-02-04 処理順と境界

1. 編成済み姫から許可属性集合を作る。
2. 報酬・店はその集合と交差する武器だけを候補にし、候補へ対象姫を添える。
3. 武器枠が満杯の姫は新武器の抽選から除外する。選択/購入候補には空き枠のある対象姫の武器だけを残し、破棄・交換を発生させない。
4. 同一`weaponDefinitionId`を低Tierから2本ずつ合成する。異なる定義・属性・所有姫をまたぐ合成は禁止する。
5. 戦闘では各所有姫を発生元として旧攻撃パラメータを解決する。主人公武器スロットは使わない。
6. セーブは新スキーマだけを読込対象とする。旧装備値の変換や混在は禁止する。

## 20-02-05 テスト観点

| ID | Yesとなる条件 |
|---|---|
| W-T-01 | 同行1/2/3人の固定seedで、候補に非編成属性武器が0件、全候補に対象姫IDがある。 |
| W-T-02 | 各姫へ4本を越えて自動装備されず、4枠満杯の姫の新武器が抽選候補から除外される。 |
| W-T-03 | Tier1×4+Tier2×2の入力がTier3×1になり、異種・異属性・別所有姫は残る。 |
| W-T-04 | 一致属性倍率だけが変わり、耐性・状態異常・隠れた属性副作用が0件。 |
| W-T-05 | 3姫×4武器、敵数・解像度・seedを記録した60秒計測で平均/1% low/最悪frame timeを保存し、最悪が16.67ms以下。 |
| W-T-06 | 旧セーブfixtureを読んでもクラッシュせず、新規開始へ誘導する。 |
